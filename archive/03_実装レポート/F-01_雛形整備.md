## 5. レビュー観点

| 観点 | 具体 |
|---|---|
| **StrictMode 二重発火** | AuthContext の起動時 fetch は `AbortController` で cancel 済み。React 19 の StrictMode 下でも安全 |
| **AuthContext の失敗経路** | 401/404/network error/JSON 検証失敗、すべて「未ログイン」に丸める(W-04 未実装時のフォールバック) |
| **ErrorBoundary の限界** | event handler / async / SSR の例外は捕捉しない。それらは F-02 の fetch ラッパ + Toast で拾う |
| **W-04 完成後の挙動** | `GET /api/auth/me` が正しい shape を返せば、AuthContext は自動で `authenticated` に。stub は自然に不要になる |
| **F-03 との契約** | LoginPage が `useLocation().state.from` を読んで `navigate(from)` する。F-03 は本 PR の RequireAuth の state 契約に依存する |
| **Modal の focus trap** | F-01 では入れない(依存 lib 増を避ける)。F-11 のアクセシビリティ調整で拾う |
| **共通コンポーネントの上書き余地** | 「minimal で defensive」に留めた。mamiyaza 復帰後に style / component 設計を上書きしやすい |
