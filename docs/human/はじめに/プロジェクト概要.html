ft_transcendence · Project Overview

cub3Dを、
ブラウザ対戦プラットフォームへ。

42の課題 cub3D（C・レイキャスティング・MiniLibX）のエンジンをそのまま、 リアルタイムのWebアプリへ発展させたブラウザ向けオンライン対戦プラットフォームです。 同じCのゲームロジックが、ネイティブ実行・ブラウザ描画用WASM・サーバ判定用WASMの 3か所で動きます。RSP（じゃんけん鬼ごっこ）チーム戦とFPS収集レースの2モードを搭載。

03 · Architecture

アーキテクチャ

サーバーが唯一の権威です。sim.wasmが30Hzで本当の試合状態を計算し、 ブラウザは直近に受け取ったsnapshotを描くだけ——勝敗を判定するコードはクライアントに 1行もありません。

04 · Tech stack

技術スタック

層選定理由
エンジンC・MiniLibX（native限定）・Emscripten→WASMcub3Dエンジンを無改造のまま描画とサーバ判定の両方で再利用。ロジックの二重管理ゼロ
フロントエンドReact + Vite + TypeScript + Tailwind CSSSSR不要のSPAで十分。TailwindでCSSフレームワーク要件を満たす
バックエンドFastify + TypeScriptNode上でsim.wasmを直接実行できる。公式WSプラグインあり
リアルタイム通信生WebSocket（@fastify/websocket）Socket.IOの抽象化は不要
DBSQLite + Prisma単一ホスト評価に適合。ORM要件を満たす
認証argon2id + opaque httpOnlyセッションCookie（JWTではない）ステートレスJWTの利点（サーバ側失効不可）がこの規模では不要
配信nginx + Docker Compose単一コマンド起動の要件
共有契約app/shared/のzodスキーマ1つの定義でFE/BE両方のバリデーションを満たす

比較検討の詳細はai/architecture.md（英語）。
