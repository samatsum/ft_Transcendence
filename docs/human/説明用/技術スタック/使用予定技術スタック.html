1データベース — 未着手 B-03
技術どのようなものかなぜ選んだか（比較対象）
SQLite 1個のファイルとして動くデータベース。独立したサーバープロセスを別途立てる必要がない。 比較対象は PostgreSQL。評価は単一のローカルマシンで行われる前提なので、 コンテナを1つ減らせる・バックアップがファイルのコピーで済む、という利点がそのまま効く。 将来 PostgreSQL へ移す場合も、ORM を挟んでいるので移行は容易。
Prisma DB のテーブルを TypeScript のオブジェクトとして扱えるようにする ORM。生 SQL を書かずに済む。 比較対象は生 SQL（better-sqlite3 等）と TypeORM。 課題書のORM モジュール（1pt）の要件をそのまま満たせること、 schema.prisma からテーブル定義と TypeScript の型を同時に生成でき、 スキーマとコードがズレないことが理由。
2認証 — 未着手 B-04 / B-05
技術どのようなものかなぜ選んだか（比較対象）
argon2id パスワードのハッシュ化アルゴリズム。生パスワードは保存せず、不可逆変換した値だけを DB に置く。 比較対象は bcrypt・PBKDF2。argon2id はメモリハード—— 専用ハードウェアによる総当たり攻撃に対して、計算力だけでなくメモリ量も要求するため強い。 ソルトが組み込みで、実装者が付け忘れる余地がない。2015 年のコンペ優勝、RFC 9106 で標準化済み。
不透明トークン
＋ httpOnly Cookie		 ログイン状態を、DB の Session 行を指すランダム文字列で管理する方式。Cookie は JS から読めない設定にする。 比較対象は JWT（採用せず）。JWT の利点はサーバー側に状態を持たない点だが、 このプロジェクトは再接続時の本人確認とログアウト即時無効化のために結局 DB を引くので、 ステートレスにする利点が消える。DB にはトークンのハッシュのみを保存する。
SameSite=Lax
＋ Origin 検証		 別サイトからの不正なリクエスト（CSRF）を防ぐ仕組み。変更系メソッドで送信元を検証する。 比較対象は CSRF トークン方式。WebSocket 側で既に Origin 検証を採用しているため、 同じ方式に統一して二重の仕組みを作らない、という判断。
3配信・起動 — 未着手 I-15
技術どのようなものかなぜ選んだか（比較対象）
nginx Web サーバー / リバースプロキシ。HTTPS を終端し、リクエストを内部の Fastify へ転送する。 比較対象は Caddy（自動 TLS が売り）。実績と日本語も含む情報量で nginx を採用。 評価要件は外部接続が HTTPS であることなので、内部の backend への転送は平文でよい。
Docker Compose 複数コンテナ（nginx・app・ボリューム）を1コマンドでまとめて起動する定義。 比較対象は無い——課題書が単一コマンドでの起動を必須としている。 現状 docker-compose.yml には Emscripten ビルド用の engine-build サービスしかなく、 nginx・app・証明書生成・マイグレーションを起動経路に組み込むのが I-15。
自己署名証明書
（mkcert 等）		 正式な認証局を通さず自分で発行する TLS 証明書。 ローカル評価環境には正式なドメインが無いため、これ以外の選択肢がない。 評価当日は接続する全マシンに CA を事前導入しないと ブラウザの警告でデモが止まる、という注意点が設計書に記録されている。

ここが評価上いちばん危ない。 I-15 が未着手なので、現状は git clone → docker compose up をしても アプリは起動せず、アドレスバーで HTTPS を確認することもできない。 これは課題書の必須要件（単一コマンド起動・全接続 HTTPS）に直接かかる。

4予備 — 未選択・着手予定なし
技術どのようなものか位置づけ
OAuth 2.0
（Google）		 外部サービスのアカウントでログインできるようにする仕組み。 予備モジュール（Minor 1pt）。Fastify に成熟したプラグインがあり、User に OAuthAccount を足すだけで済むため候補に入れている。
2FA
（TOTP）		 パスワードに加えて、時間で変わる6桁コードを要求する二要素認証。 予備モジュール（Minor 1pt）。ライブラリと QR 表示、認証画面1枚の追加で済む見込み。
Prometheus
＋ Grafana		 サーバーの状態を数値として収集し（Prometheus）、グラフとして可視化する（Grafana）監視ツール。 予備モジュール（Major 2pt）。compose にコンテナを2つ足し、Fastify に計測用エンドポイントを生やす形。ゲーム本体と独立しているので着手が遅くても成立する。

この4つ目の節だけ性質が違う。 上の1〜3は「やると決まっているがまだ書いていない」もの。この節はそもそも採用を決めていない。 必須 14pt ＋ ボーナス 5pt が確実になるまで着手しない方針で、 動かないモジュールを申告すると 0pt になるため、完成したものだけを評価当日に申告する。
