02 — Required Roles

管理役割の枠（課題書 II.1.1）

課題書 II.1.1 は PO / PM・スクラムマスター / テクニカルリード / 開発者（全員）の割当を義務づけ、 README.md への明記を求めている。この枠組みは維持し、現状は samatsum が全役割を兼任する。 残りの人数分は将来の合流に備えた空きスロットとして扱う。

管理役割主な責務現在の担当
プロダクトオーナー (PO) 機能の優先順位付け、完了検証、バックログ管理、評価者との窓口 samatsum（兼任）
空きスロットあり
プロジェクトマネージャー / スクラムマスター 進捗・期限の追跡、ブロッカー管理、定例の調整 samatsum（兼任）
空きスロットあり
テクニカルリード / アーキテクト アーキテクチャと技術決定、重要変更のレビュー（sim / WS プロトコル境界） samatsum（固定）
cub3D エンジンの設計・実装元
開発者（全員） 実装・コードレビュー・自分の実装のテスト・文書化 samatsum

テクニカルリードのみ samatsum 固定（エンジンの設計・実装知識を要するため）。 PO と PM・SM は、新メンバーが加入した時点で希望・得意に応じて配分し直せる。

03 — Development Lanes

開発レーン構成（Engine / Backend・DevOps / Frontend / Gameplay）

4レーン構成そのものは課題書の想定に沿った枠組みとして維持する。 現状は全レーンを samatsum が兼務しており、Backend・DevOps と Frontend は 本来複数人で分担する前提だったレーンのため、空きスロットが大きい。

Engine

Cエンジン本体

native / web / sim の3ターゲット、sim 公開 API、snapshot 受け口など。現在は samatsum が担当。

Backend・DevOps

サーバー基盤・ゲームサーバー・インフラ

Auth / REST / DB / DevOps と、WS・GameRoom・sim.wasm 駆動。現在は samatsum が兼務。 空きスロットあり

Frontend

フロント基盤・フロントゲーム

認証・ロビー・プロフィール画面と、GameView / HUD / ゲーム統合。現在は samatsum が兼務。 空きスロットあり

Gameplay

対戦ロジック・マップ

戦闘員統合・先取点・対戦マップなど。現在は samatsum が担当。

04 — Unresolved Risk

未解決リスク：人数要件との齟齬

未解決。 課題書は本プロジェクトを4〜5人のグループプロジェクトと定義しており（課題書 II章）、 II.1.1 の必須役割割当もその人数を前提にしている。 一方でリポジトリ直下の README.md「チーム役割 (Team Roles)」節（第VI章 要件対応）は、 現時点でも旧チーム4名（samatsum / torinoue / mamiyaza / hminemur）を列挙したままであり、 本ページが示す「samatsum 単独稼働」という実態と一致していない。

この齟齬は本書では解消しない。新メンバーが合流するか、 README側の記載を単独稼働の実態に合わせて更新するか、 いずれかの判断がなされるまで未解決のまま残す。
