Explanations — .cub map format

.cubマップ書式

ゲームのステージを 1 枚のテキストファイルで表したものが .cub です。 上半分が「設定」、下半分が「地図（文字で描いた見取り図）」という構成になっています。 このページは全体像をつかむための解説で、対象はチームメンバー全員 （とくにマップを触る人）です。

正本はこちら — 1 文字ずつの厳密な仕様は ユーザードキュメント §4（.cub 記述ルール）が正本です。 実際にマップを書く・直すときはそちらを参照してください。このページは 「なぜそうなっているか」を理解するための補助教材です。

01 / Structure

.cub は 2 段構成

.cub ファイルは、上半分の「設定ヘッダ」と下半分の「マップ本体」から できています。 

┌─ 設定ヘッダ ────────────────┐
│ R 1920 1080                 │  解像度
│ NO ./textures/wall/...xpm   │  壁テクスチャ（北）
│ F 184,113,39                │  床の色
│ ...                         │
├─ マップ本体 ────────────────┤
│ 1 1 1 1 1 1 1               │  1 = 壁
│ 1 0 0 0 N 0 1               │  0 = 床、N = スポーン地点
│ 1 1 1 1 1 1 1               │
└─────────────────────────────┘

上：設定ヘッダ

解像度・テクスチャのファイル名・色・敵の速度などを キー 値 の形で 並べる。

下：マップ本体

1（壁）や 0（床）などの文字を並べて、上から見た ステージの見取り図を描く。

02 / Map characters

マップ本体で使う主な文字

.cub のマップ部分は、決まった文字だけで構成されます （C 側の許可集合 VALID_MAP_CHARACTERS＝config.h）。 よく使うものだけ抜き出すと次の表のとおりです。

文字意味
1壁（通れない）
0床（通れる）
N S E Wスポーン地点（戦闘員の初期位置。向きも表す）
M敵（ハザード）。巡回し、見つけると追跡してくる
P敵の巡回路
k〜o収集アイテム（星）
D扉（全部集めるまでは壁、集め終わると開く）
Gゴール（先に踏んだ戦闘員が勝ち。FPS のレース用）
a〜e / f〜j障害物オブジェクト（通行不可 / 通行可）
重要 — マップ文字 G・D・M は 新設したものではなく、元の cub3D に既にありました。オンライン対戦化 （G-06〜G-08）でやったのは「勝者を席に帰属させる」等のルール調整で、 マップ書式そのものは足していません。

03 / RSP vs FPS

RSP と FPS の区別は「置き場所」で決まる

同じ .cub でも、どのフォルダに置くかでモードが決まります。 

maps/rsp_map/  に置いたマップ  →  RSP モード（2vs2 じゃんけん）
maps/fps_map/  に置いたマップ  →  FPS モード（1vs1 レース）

これは native も web も同じルールです。main.c（native）も web_init の呼び出し側（JS）も、パスに rsp_map/ が 含まれるかを見てモードを切り替えます。ファイルの中身に「これは RSP です」とは 書きません。置き場所がモードの宣言です。

スポーン文字とチームの対応（RSP）

RSP では、スポーン文字がそのままチーム分けになります。

文字チーム
N W赤
S E青

だから RSP マップは、赤 2 席・青 2 席が別マスに立つように N W S E を配置します （下の rsp.cub の例では各文字が 2 つずつありました）。

ハマりどころ — RSP は 1 チーム 2 席（RSP_TEAM_SPAWNS = 2） 使う設計です。赤は N/W の合計、青は S/E の合計で、それぞれ最低 2 マスのスポーン地点が必要です。マップに置く数が 足りないと、席を割り当てられずにセットアップに失敗します。

04 / Gated race

FPS の「関門レース」の作り方

FPS のオンライン対戦マップ（例 fps_duel.cub）は、D と G を組み合わせて関門付きのレースを作ります。 

収集アイテム(k〜o)を全部集める → 扉(D)が開く → ゴール(G)へ走る → 先に踏んだ方が勝ち
  • G を置かないマップは、「全部集めて扉を開ける」ところまでが目的 （従来の cub3D 的な遊び）。
  • M（敵ハザード）を通り道に置くと、接触＝数秒リスポーン待ちの 妨害になります（G-08）。
自動確認あり — この「収集 → 扉 → ゴール」の関門が最後まで 通れることは、make test の G-09 検査が自動で確認しています。

05 / Whitelist

オンライン対戦では「ホワイトリスト」しか使わない

maps/ には開発・テスト用の .cub がたくさんありますが （door_test.cub など）、オンライン対戦で使えるのは、サーバに 登録された 4 枚だけです。

id名前モードファイル
rsp（RSP 標準）rspmaps/rsp_map/rsp.cub
rsp_pillarsPillarsrspmaps/rsp_map/rsp_pillars.cub
21x21_arenaArena 21fpsmaps/fps_map/21x21_arena.cub
fps_duelDuel Runfpsmaps/fps_map/fps_duel.cub

これをホワイトリストと呼びます（③§2-E）。理由は 2 つあります。

  1. 安全: 利用者が任意のファイルパスを送ってサーバのファイルを 読ませる、といった攻撃を防ぐ。サーバは「登録済みの id」しか受け付けない。
  2. 品質: 対戦バランスをテストプレイで確認したマップだけを出す。

流れ（W-14 の仕事）

クライアント「マップ id = fps_duel で対戦したい」
        │
サーバがホワイトリスト表で id → ファイルパスを解決
        │
サーバが .cub を読み、その中身（テキスト）を welcome.map_text として配布
        │
各ブラウザは受け取ったテキストで render.wasm を初期化して描く
ポイント — サーバがマップの中身そのものを配ります。クライアントに ファイルパスを渡してファイルを読ませたりはしません（②§5-B）。

06 / Summary

まとめ

1.cub は上＝設定ヘッダ / 下＝文字で描いた地図の 2 段構成。
2マップは決まった文字だけで描く（1壁 0床 N/S/E/Wスポーン M敵 D扉 Gゴール…）。
3G D M は元からある文字。オンライン化で新設していない。
4RSP か FPS かは、置くフォルダ（rsp_map/ / fps_map/）で決まる。
5RSP はスポーン文字がチーム分け（N/W=赤、S/E=青）。
6オンラインではホワイトリスト登録の 4 枚だけ。サーバが中身を配る（W-14）。

FAQ

コード想定 Q&A から（.cub 関連のみ）

テクニカルリード自己確認シートのうち、マップ書式・解析に関する項目だけを ここに集約しています。

Q. RSP か FPS かはどう決まる？

A. マップの置き場所。maps/rsp_map/ なら RSP、 maps/fps_map/ なら FPS。.cub の中身では宣言しない。 RSP のスポーンは N/W=赤・S/E=青。

確認: common/main.c:97（set_mode_from_path）

Q. マップ文字 G（ゴール）は新設した？

A. していない。IS_GOAL セル + goal_tex は元から 実装済み。G-06 は「勝者を席 id に帰属させる」だけ。D（扉） M（敵）も元からある。

確認: config/config.h（IS_GOAL / DOOR_CHAR / VALID_MAP_CHARACTERS）

統合元: md_files/説明用/cubマップの読み方.md（archive/ に移設）
